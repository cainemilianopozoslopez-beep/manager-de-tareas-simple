1. QUÉ ES
------------------------------------------------------------------------
Un gestor de tareas personales con estética Gmail (en el código está
renombrado como "Pulse Matrix" — es el mismo proyecto). Era una app
full-stack que funcionaba SOLO EN LOCAL. Ya se migró el código a
Firebase (Auth + Firestore); SOLO FALTA crear el proyecto real de
Firebase y conectar sus claves para que quede funcionando en internet.

Es un proyecto chico, autocontenido, sin dependencias de pago ni build
nativo.


2. STACK TÉCNICO
------------------------------------------------------------------------
CLIENTE (client/) — ACTIVO, es lo único que se usa ahora
  - React 19 + Vite 8
  - Sin router ni librería de estado: TODO el estado vive en App.jsx
    (~1000 líneas, useState/useEffect, props hacia abajo)
  - Estilos inline (style={{}}), iconos con lucide-react
  - Es una PWA (service worker propio en public/sw.js, manifest, íconos)
  - firebase 12 instalado y CONECTADO: Auth (email/contraseña) +
    Firestore (tareas, ajustes, respaldo)
  - vercel.json listo (config de despliegue SPA)
  - 15 componentes: TaskList, TaskItem, TaskModal, Login, SettingsModal,
    ProfileModal, EmailPreviewModal, CalendarView, StatsDashboard,
    MatrixView, PulseHeader, PulseSidebar, etc.

SERVIDOR (server/) — YA NO SE USA, queda como código legacy
  - Express 5 + SQLite (node:sqlite), nodemailer + node-cron
  - Ningún archivo del cliente le pega más (se quitó todo localhost:5000)
  - Se puede borrar sin romper nada, o dejarlo como referencia para el
    envío de emails (ver punto 10)

No hay monorepo: son dos carpetas vecinas coordinadas por scripts en el
package.json raíz.


3. MODELO DE DATOS (ahora en Firestore, por usuario)
------------------------------------------------------------------------
Estructura: users/{uid}/tasks/{taskId} y users/{uid}/settings/main

TAREA: id, title, description, priority (urgente/alta/media/baja),
  category, dueDate, dueTime, recurrence (none/daily/weekly/monthly),
  subtasks (array {id, text, done}), starred, done, trash, timestamps.

SETTINGS: theme, notificationMode (browser/gmail/both), senderEmail,
  senderPass (app-password de Gmail, en pausa — ver punto 4),
  recipientEmail, scheduledTime, autoSendEnabled, lastSentAt/Status.

6. EL ESTADO REAL — QUÉ SE HIZO Y QUÉ FALTA
========================================================================
Antes el proyecto tenía TRES caminos de datos a medias (Firestore
inactivo, Express solo local, invitado). Eso YA SE ARREGLÓ en el código:

  [1] FIRESTORE (nube) -> AHORA ES EL ÚNICO CAMINO PARA CUENTAS REALES
      Login.jsx llama de verdad a Firebase Auth (email/contraseña), el
      usuario recibe un uid real, y TODO (tareas, ajustes, lote,
      respaldo, perfil) pasa por Firestore. Se sacaron los 12 lugares
      que apuntaban a localhost:5000.

  [2] EXPRESS + SQLITE -> RETIRADO del flujo del cliente
      El código sigue en server/ pero nada lo llama. Puede borrarse.

  [3] INVITADO (guest) -> SIGUE IGUAL
      En memoria + sessionStorage, no persiste. Sin cambios.

LO QUE FALTA (y es TODO lo que falta) es un solo paso externo:
CREAR EL PROYECTO REAL DE FIREBASE. Ahora mismo el código usa una
config de Firebase "dummy" (claves de relleno) porque no existe un
archivo .env con las claves reales — ver punto 10 para los pasos
exactos.

10. LO QUE NECESITO DEL EXPERTO (o para hacer yo mismo con guía)
========================================================================
Ya NO hace falta decidir arquitectura ni reescribir código de
autenticación/datos — eso está hecho. Lo que queda es:

PASO 1 — Crear el proyecto de Firebase (5-10 min, requiere cuenta Google):
  1. console.firebase.google.com -> Crear un proyecto
  2. Authentication -> Sign-in method -> activar "Correo/contraseña"
  3. Firestore Database -> Crear base de datos -> modo producción
  4. Configuración del proyecto -> Tus apps -> Agregar app Web ("</>")
  5. Copiar las 6 claves (apiKey, authDomain, projectId, etc.) a
     client/.env (usando client/.env.example como plantilla)
  6. Pegar el contenido de firestore.rules en Firestore > Reglas ->
     Publicar

PASO 2 — Probar en local:
  cd client && npm run dev
  Registrar una cuenta real, crear tareas, confirmar que persisten.

PASO 3 — Desplegar:
  Cargar las mismas 6 variables VITE_FIREBASE_* como Environment
  Variables del proyecto en Vercel, y volver a desplegar
  (manager-de-tareas-simple.vercel.app ya existe y está conectado
  al repo de GitHub).

FASE 2 (opcional, más adelante) — Envío automático de emails:
  Requiere una función serverless (Vercel Function o Firebase Cloud
  Function) que guarde la contraseña de Gmail fuera del cliente y
  dispare el envío. server/mailer.js ya tiene la lógica de generar el
  HTML y mandar el correo con nodemailer — se puede portar casi tal
  cual a esa función en vez de reescribirla de cero.


EN UNA FRASE:
  El código YA está migrado a Firebase; solo falta crear el proyecto
  real, cargar sus claves, y volver a desplegar. El envío de emails
  queda como una mejora aparte para más adelante.
